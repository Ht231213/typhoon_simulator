# 水深掩膜 (WPAC_SHELF*.png) 生成说明

> 由 **GMT 6.7.0** (`C:\programs\GMT6\bin\gmt.exe`) + **ffmpeg** 生成。
> 地形数据：GMT 远程 `@earth_relief_01m`（SRTM15+ v2.7，1 弧分）。

## 1. 结论速览

- 三张图尺寸均为 **1772 × 1418**（与 `WPAC.png` / `WPAC_LAND.png` 完全一致）
- 像素只有**纯黑**(0,0,0) + **透明**；alpha 只有两个值 `{0, 255}`，无中间值
- **不透明 = 该区域适用**（即“浅于该阈值”）
- 占比单调递增：20m 37.32% < 50m 39.74% < 100m 42.78% ✅
- **流程已复刻验证**：用同一套命令复刻 1000 m 掩膜，与现有 `WPAC_LAND1000.png`
  逐像素比对 **IoU = 1.00000000**（错配 0 像素，颜色统计逐项相同）

## 2. 阈值与语义（关键）

高程数据里**海洋是负值**。所以“水深浅于 D 米” ⇔ **高程 > -D**。

`grdclip -Sb<low>/<high>` 的语义**已实测确认**：

```text
gmt grdclip @earth_relief_01m -R90/190/-10/70 -Sb1000/NaN -Gt1000.nc
gmt grdinfo t1000.nc   ->   v_min: 1000   v_max: 6837
```

即 **`-Sb<low>/NaN` = 保留 ≥ low 的值，把低于 low 的设成 NaN**
（和 GMT 文档字面“范围内设 NaN”听起来相反；`-Si` 才是那个语义）。

所以本任务用的是 **`-Sb-<D>/NaN`**（负号），保留高程 ≥ -D。

## 3. 完整命令

对每个 D ∈ {20, 50, 100}（下面以 D=100 为例）：

```bat
set GMT=C:\programs\GMT6\bin\gmt.exe

REM 1) 按高程切：保留高程 >= -100
"%GMT%" grdclip @earth_relief_01m -R90/190/-10/70 -Sb-100/NaN -G"D:\...\shelf100.nc"

REM 2) 造 CPT：-100..9000 全黑
"%GMT%" makecpt -Cblack -T-100/9000 > "D:\...\shelf100.cpt"

REM 3) 出 PS
"%GMT%" grdimage "D:\...\shelf100.nc" -JQ15c -R90/190/-10/70 -C"D:\...\shelf100.cpt" > "D:\...\shelf100.ps"

REM 4) PS -> PNG（-A 裁到图框，得到精确 1772x1418 @300dpi）
"%GMT%" psconvert -A -TG -F"D:\...\shelf100" "D:\...\shelf100.ps"

REM 5) 抠背景：白/灰 -> 透明
ffmpeg -y -i "D:\...\shelf100.png" -vf "format=rgba,colorkey=white:0.5:0.1" -pix_fmt rgba -frames:v 1 "G:\typhoon\assets\images\WPAC_SHELF100.png"
```

> 可复现脚本：`G:\typhoon-tools\水深掩膜工具\make_shelf.bat`
> （脚本刻意**放在项目外**，避免 Godot 扫描/导入非资源文件；`docs/` 下已放 `.gdignore`。）

固定投影/图幅（与现有掩膜一致）：`-R90/190/-10/70 -JQ15c`，300 dpi，最终 1772×1418。

### 踩过的坑（重要）

1. **GMT 不在 PATH 里**，必须写全路径 `C:\programs\GMT6\bin\gmt.exe`。
2. **千万不要用 PowerShell 的 `>` 重定向**写 `.cpt` / `.ps` 文件 ——
   PowerShell 会写成 UTF-16 带 BOM，GMT 直接报
   `Current file position is 2` / `GMT_CPT_READ_ERROR`。
   **要用 `cmd /c "... > file"`**，或让 GMT 自己写文件。
3. `-JQ15c/0` 这种写法是**错的**（transcript 里踩过），正确的是 **`-JQ15c`**。
4. `makecpt -Cblack -T<lo>/9000` 生成的 CPT 自带 `N 128`，所以 NaN 区域渲染成
   **灰(128,128,128) 而不是纯白**。ffmpeg `colorkey=white` 会把灰一起抠掉
   （实测确实如此：灰(128) 全部变透明，黑色保留），所以能正常工作。
5. ffmpeg 输出单张图要加 **`-frames:v 1`**，否则会警告
   `does not contain an image sequence pattern`。

## 4. ⚠ 陆地怎么处理的：**方案 (a)** —— 用户已拍板

**采用方案 (a)：陆地也标成不透明（不剔除陆地）。这是用户最终确认的决定。**

原因：高程阈值切出来的结果**必然包含全部陆地**（陆地高程 > 0 > -20 > -50 > -100），
这是方案 (a) 的固有结果，也是任务卡推荐的做法。

> **陆地由游戏侧排除**：本目录下三张 `WPAC_SHELF*.png` 一律**不抠陆地**，
> 游戏代码负责用现有的 `WPAC_LAND.png` 把陆地减掉。
> 也就是说：**不要**用我这几张图去合成 `WPAC_LAND.png`，两者职责分开。

### 4.1 陆地 vs 浅水：各占多少（Lead 核对代码用）

陆地基准 = `WPAC_LAND.png` 的 **`alpha == 255`**（推荐阈值，理由见 4.2）。

| 掩膜 | 占画面 | 选中像素 | 其中陆地 | **真正的浅水** | 陆地占本掩膜 | 浅水占本掩膜 | 浅水占全画面 |
|---|---|---|---|---|---|---|---|
| 20m | 37.32% | 937778 | 906166 | **31612** | 96.63% | 3.37% | 1.258% |
| 50m | 39.74% | 998543 | 907566 | **90977** | 90.89% | 9.11% | 3.621% |
| 100m | 42.78% | 1075006 | 908280 | **166726** | 84.49% | 15.51% | 6.635% |

**浅水部分单调递增：1.258% < 3.621% < 6.635% ✅**
（陆地占画面 36.42%，是 `WPAC_LAND.png` 的 alpha≥128 区域。）

### 4.2 给代码的取值建议（重要）

陆地基准请用 **`alpha == 255`**，**不要**用 `alpha > 0`。
`WPAC_LAND.png` 的 alpha 存在抗锯齿中间值（9 / 139 / 179 / 239）：
`alpha>0` 会多框进 **5074** 个边缘像素（915121 vs 910047），
这些像素大量位于海岸线附近的浅水，会误伤真正的浅水判定。
用 `alpha==255` 则浅水为 1.258% / 3.621% / 6.635%；
用 `alpha>0` 会缩到 1.127% / 3.458% / 6.457%（结论不变，但建议前者）。

### 4.3 结论

- `WPAC_SHELF20.png` 有 **96.6% 是陆地**，真正"水深浅于 20 m 的海面"只有 **1.26%** 画面。
- 即使 100 m 档，陆地仍占本掩膜的 **84.5%**。
- 所以**游戏代码里必须剔除陆地**，否则会把亚洲大陆当成"浅海暖水层不够厚"的区域，
  逻辑会反掉（陆地不该抑制台风，也不该被当成浅海）。
- 等价写法：`SHALLOW = SHELF20 & ~(LAND_ALPHA == 255)`。

## 5. 分档自检

```text

  50m \ 100m : 落在 50m 但不在 100m 的像素 = 0
  单调性: 0.373216 < 0.397399 < 0.427830
纯浅水部分（alpha==255 基准）同样单调:
  0.012581 < 0.036212 < 0.066350  ✅
交叉验证: 三张掩膜都完全包含现有 WPAC_LAND1000.png 的 239119 个像素 ✅
          (即所有 >1000m 的高山都同时满足高程 > -20/-50/-100，符合预期)
```
